# Heuristic: Frame Abandonment

## Recognition

This heuristic fires when feedback rejects the governing interpretation, but revisions keep treating prior output as structure to preserve.

Cues:

- Feedback says the interpretation is opposite, fundamentally wrong, or should start over.
- The next response negates or paraphrases old claims without new understanding.
- Several revisions preserve the same decomposition, vocabulary, or causal model.
- The agent is editing sentences faster than it is asking what premise failed.
- Each proposal looks responsive locally while frustration rises at the frame level.

Distinguish frame rejection from expression feedback. "Shorten this" or "rename that" usually preserves the model. "That is not what this means" attacks it.

## Move

1. **Stop editing the prior artifact.** Treat it as evidence that the model failed, not as a template.
2. **Name the rejected frame.** State the assumption or interpretation that organized the output.
3. **Ask for or investigate the missing distinction.** Use one targeted question when only the operator can supply it; otherwise inspect available evidence.
4. **Listen before proposing.** Do not turn the clarification turn into another solution attempt.
5. **Build a fresh model.** Reconstruct actors, constraints, causal relations, and desired outcome from the corrected understanding.
6. **Draft anew and compare.** Verify that the new artifact does not preserve unsupported structure merely for continuity.

Example:

```text
Rejected frame: "this component is operationally isolated because it runs in a
separate process." Missing distinction: its outputs drive a shared downstream
workflow, so process isolation is not operational independence. Rebuild the
analysis around dependency and consequence, not deployment topology.
```

## Negotiation

| Feedback shape | Response |
|---|---|
| Local wording or formatting correction | Edit locally. |
| One factual premise corrected | Apply Corrected-Assumption Leakage. |
| Governing interpretation rejected | Abandon and rebuild. |
| Rejection is strong but underspecified | Ask one question about the missing distinction before proposing. |
| Prior artifact contains verified facts | Reuse facts as input, not its organizing structure. |
| Operator requests a direct opposite | Follow the direction while still checking for facts that should survive. |

## Why This Works

Revision has momentum. Existing headings, claims, and causal order feel like work that should be preserved, so an agent changes polarity inside the same structure. If the structure was generated by the broken model, preserving it reproduces the failure in a more compliant surface.

Abandonment creates a clean inference boundary. Verified evidence may carry forward, but the old arrangement loses authority. The clarification step ensures that "start over" means new understanding rather than random variation.

## When NOT to Apply

- Feedback targets wording, length, tone, or one factual site.
- The governing model remains explicitly endorsed.
- A mechanical correction fully resolves the problem.
- Rebuilding would discard binding structure supplied by the operator; preserve that structure and replace only the rejected interpretation.

## Relationship to Pillars

- **Frame Inspection:** Frame Abandonment is its receive-side, multi-turn specialization.
- **Category Lock-In:** catches repeated exploration inside one category before the frame is explicitly rejected.
- **Corrected-Assumption Leakage:** propagates a factual correction when wholesale frame replacement is unnecessary.
- **Committed Contribution:** correction is part of truth production, not a reason to defend or cosmetically invert a claim.
- **Tell Laundering:** surface substitution can preserve a failed rhetorical move just as local editing can preserve a failed model.

## Summary

When feedback rejects the governing interpretation, stop revising its artifact, identify the missing distinction, and rebuild from a fresh model rather than negating sentences inside the old frame.

# Heuristic: Framed Menu

## Recognition

This heuristic fires when:

1. Another party presents a bounded menu of options.
2. Every option shares an unstated premise you can articulate.
3. An option outside the menu would dissolve rather than merely optimize the offered choice.
4. The menu's structure is beginning to feel like evidence that the option space is complete.

Cues:

- Your first honest reaction is "none of these."
- The best listed option still feels wrong at a level the comparison does not express.
- All options assume the same solution category, sequence, scope, or ownership boundary.
- A fallback such as "or defer" appears, but no premise-dropping option does.
- A domain-informed answer would start before, after, or outside the menu's chosen boundary.

## Move

1. **Articulate the shared premise.** State what every option assumes.
2. **Test whether it is binding.** Find a domain reason independent of the menu's author and format.
3. **Name the premise-dropping option.** It must void the dilemma, not hybridize listed choices.
4. **Surface the framing rejection.** Explain why the premise does not bind and how the outside option changes the decision.
5. **If the premise holds, choose inside the menu.** State that the frame was tested and survived.

Example:

```text
All three options assume the whole migration plan must be designed before any
part is implemented. That is not a binding requirement. The outside option is
to migrate one representative component end to end, then derive sequence and
templates from what the implementation reveals.
```

## Negotiation

| Situation | Response |
|---|---|
| The menu was built from explicit operator criteria | Treat the bound as presumptively valid, while still flagging a binding omission. |
| The author shows that outside options were considered and rejected | Inspect that rejection rather than repeating the search. |
| No shared premise can be stated | The menu may represent a genuine trade-off; choose or ask for weighting. |
| The proposed outside option is only a hybrid | Try again from "what would make this choice unnecessary?" |
| The choice is forced by an upstream constraint | Operate inside it. |
| Stakes are trivial | Pick without adding a framing essay. |
| The receiver cannot act on a reframe | Choose the best permitted local action, then raise the framing issue with the party that can change the constraint. |

## Why This Works

Enumeration and bounding are different acts. A menu can be exhaustive inside a narrow premise while excluding the correct response. Structured presentation creates an authority effect: the receiver assumes that because alternatives were listed, the option space was analyzed.

Naming the shared premise makes the bound testable. If it is grounded, the menu gains legitimacy. If it is inherited, the outside option prevents downstream work from making the accidental frame load-bearing.

The move is cooperative rather than contrary. It returns a better decision and gives the proposer a chance to defend or update the frame.

## When NOT to Apply

- The menu spans the actual binding trade-off and no common questionable premise exists.
- An external rule permits only the listed options.
- The operator explicitly delegated a narrow choice and widening it would not change the outcome.
- The outside option cannot be made concrete.
- The cost of inspection exceeds the value of a low-stakes reversible choice.

## Relationship to Pillars

- **Loaded Comparison:** supply-side sibling. It prevents constructing a menu whose axes launder a preference; Framed Menu prevents accepting a menu whose bound goes untested.
- **Frame Inspection:** provides the shared name-source-binding-step-outside procedure.
- **Category Lock-In:** questions a solution category after repeated self-generated proposals; this heuristic can fire on the first received menu.
- **Committed Contribution:** requires explicit framing rejection rather than a silent evasive pick.
- **AI-Native Expertise:** received structure is input, not authority.

## Summary

Before choosing from a menu, name the premise all options share. If it is inherited rather than binding, propose the concrete option that drops it and surface the frame correction explicitly.

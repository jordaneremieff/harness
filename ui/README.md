# Web harness

A local browser interface for ordinary Pi conversations and retained Durable agents. The terminal harness remains independent: the UI does not load as a Pi extension and imports no extension source. Its agent links use the public package-level [transport entrypoint](../transport/index.ts). Stop this process to return to terminal-only use.

## Start

```sh
npm run ui
```

This builds the browser modules, starts a supervisor for the current directory, and opens the launch URL in the default browser. Pass flags after `--`, for example `npm run ui -- --cwd <project-directory>`. For manual browser startup, use `npm run ui:start -- --cwd <project-directory>` and open the printed launch URL yourself. The CLI enables source updates and serves a confirmed in-memory browser generation; `npm run ui:build` remains the explicit retained-browser build. Press Ctrl-C to stop the supervisor, browser links, and owned primary processes, not independent Durable agent work. The page removes its launch fragment and exchanges it for an HttpOnly cookie. Starting a Primary or opening a saved session is an explicit action; backend startup and tab refresh never create a primary or send model input. First use shows saved sessions inline for the launch directory; a deliberate switch uses the same list in a dialog. Passive working-folder text sits beside a named folder SVG control that opens the anchored **Working folder** chooser. Every project label uses the shortest path suffix unique among the listed directories; repeated sessions in the same directory share that label. A leading slash identifies a complete directory when it is also a suffix of another path. Full path data remains unchanged in titles, descriptions, and actions. The menu loads recent projects automatically and retains explicit refresh and pagination. A listed folder selection changes only the workspace's browse folder; it does not select or start a Primary or show saved sessions. **Other folder…** opens the explicit directory form and changes the same browse folder. File selection displays content in the focused main pane without changing the retained conversation selection. **Sessions** focuses the inline list on first use and uses the same chooser in a dialog only when a conversation occupies the main region. **Session file…** reveals an exact JSONL path without removing the selected project, search, or list.

Flags:

| Flag | Meaning |
| --- | --- |
| `--cwd` | Launch-directory suggestion; the directory must exist. |
| `--port` | Local TCP port, default `4318`; `0` requests an assigned port. |
| `--pi` | Pi executable, default `pi` on PATH. Arguments are supplied as an array, without a shell. |
| `--state-dir` | Private UI state directory; default `<agentDir>/ui`. |
| `--open` | Open the launch URL in the default browser through the macOS `open` command after the backend listens. A failed open leaves the backend running and prints the URL. |
| `--dev-reload` | Enable source updates; the CLI already enables this mode. |

The backend uses native Node TypeScript stripping; runtime files contain only erasable TypeScript. Browser modules compile through `tsc` to `dist/web`; generated output is ignored. No bundler, framework, transpilation loader, or new runtime package is required.

`PI_CODING_AGENT_DIR` selects the Pi agent directory; otherwise the usual home-relative Pi directory applies. `PI_AGENT_SESSIONS_DIR` selects the retained agent store; otherwise it is `<agentDir>/agent-sessions`.

## Ownership and terminal return

Each explicitly opened ordinary primary has a backend key and conversation epoch. Refresh and tab close preserve its process. Drafts and actions capture the exact key/epoch or Durable identity; a session replacement rejects old-epoch actions. A primary's accepted input is not proof of a completed model answer. Execution becomes idle on `agent_settled`. Completed manual compaction uses an authoritative state refresh guarded by the conversation epoch, lifecycle, and activity revision; newer activity takes precedence.

Use **Continue in terminal** to release an ordinary primary:

1. Choose whether to wait for accepted work or abort it, and whether to clear its queue.
2. The backend freezes admission, retains cleared-queue recovery copies, and verifies a saved file.
3. The backend closes RPC stdin and waits for the child to exit.
4. Only after exit does it return the quoted project and `pi --session` command.

An empty, unpersisted session has no resume command. A blocked exit has no successful handoff command. The UI never launches a terminal, takes another process's PID, or kills a writer to claim the file.

A failed transport or failed initialization does not prove child exit. Such a child still owns its saved file and primary capacity. If shutdown cannot confirm exit, the backend retains its state-root lock. After verified exit, it completes local state cleanup without a takeover or process signal. Pending primary opens stop before shutdown releases state ownership.

After you exit Pi in the terminal, choose **Resume here** in **Ready for terminal** to reopen that exact saved conversation directly. The action uses the handoff receipt's working folder and saved file without a list refresh, search, or another confirmation. **Open session…** remains available to choose a different conversation. Neither the handoff result nor terminal exit starts a browser primary automatically.

Opening a saved session is itself the deliberate resume action: **Resume here**, or the click or Enter on a saved row, starts the primary on that exact file with no separate confirmation step. After a backend restart, an explicit open of the same verified saved conversation reuses its retained primary key and conversation epoch. Its workspace keeps the acknowledged draft, reading position and presentation. Explicit Resume selects the returned Primary tab; ordinary refresh preserves the current layout. The server's selection of the returned session does not cancel that explicit action. A canceled picker or later workspace, pane or conversation choice prevents delayed selection and focus. Other input during Resume suppresses late composer focus without canceling the admitted selection. Recovery requires both the canonical file and saved-session identity to match; ambiguous or changed identities are refused without transferring state. Restart alone starts no primary and replays no input or uncertain operation. Pi exposes no public saved-file writer lock or owner query, so the backend cannot detect a terminal or other external writer; close that writer yourself before you open the file here. The backend rejects duplicate canonical files within its own registry, refuses a file another backend primary already writes, and selects an already open backend session instead of opening it again. Each active process keeps its own in-memory branch; the UI does not read later writes from another active process. Concurrent writers can create separate branches. Stop both writers before reopening the saved session. Inspect and select branches with Pi’s `/tree` command; this UI does not merge branches. There is no automatic terminal-to-browser attachment.

Startup extension errors are initialization warnings with bounded text. Their presence or absence does not establish exclusive session ownership.

## Supervisor and recovery

The CLI keeps one backend in a separate owned process group. It preserves the selected TCP port across replacement, including an initially assigned port. After an abnormal exit, it verifies that the old backend group is absent before it starts a replacement. The third abnormal exit within a rolling minute stops the supervisor; earlier replacements wait 100 ms and 200 ms. A requested source restart does not consume that crash allowance. Startup has a 45-second deadline. Stop and source restart allow five seconds for graceful close. Remaining members of the recorded backend group receive SIGKILL, followed by at most five seconds of exit verification. Unconfirmed cleanup stops replacement rather than taking another owner's resources.

Shutdown first stops HTTP admission and event streams. It drains Auth publication, files, builds, diagnostics and logging before Registry releases private state. A pending primary exit or queue-recovery write retains state ownership and permits another shutdown request. Fatal unhandled rejection or uncaught exception uses the same close path and exits nonzero, with a finite shutdown deadline; the backend does not continue after that condition. A restart never replays prompts or uncertain effects. Opening a saved ordinary session remains explicit.

A failed file or agent worker reports unavailable while its adapter attempts recovery. Each adapter permits at most three replacement workers over its lifetime, without idle retry polling. Recovery requires confirmed startup before safe watch scopes or confirmed agent observations return. It does not repeat pending mutations, input, aborts, or configuration. Retained admission receipts and recovery copies remain authoritative. An uncertain file effect permanently disables file-worker recovery for that backend run and blocks file identities; inspect the affected paths before a deliberate backend restart. Worker exit never proves that a filesystem effect was canceled.

The private `lifecycle.log` retains a recent window of redacted startup, replacement, shutdown-request, fatal-class and control records. Its limits are 64 KiB, 128 records, and 512 characters per detail, with at most 64 control records in that window. Oldest control records leave first when their limit is reached; the total byte and record limits still apply to every event kind. One coalesced writer closes before the state lock releases. The supervisor discards oversized diagnostic lines, redacts complete lines before terminal relay, and caps relayed diagnostics at 64 KiB for its lifetime. Launch URLs, cookies, input bodies and raw error stacks do not belong in retained logs. Log failure does not grant state ownership or turn a failed operation into success.

## Agent presentation control

An ordinary or Durable agent uses the standalone command from a local shell. It is not a Pi extension:

```sh
node ui/cli/control.mts --help
node ui/cli/control.mts layout
node ui/cli/control.mts --workspace <workspace-id> layout
node ui/cli/control.mts --workspace <workspace-id> --actor <label> '{"action":"show","rootId":"<registered-root-id>","path":"README.md","preview":true}'
```

`--state-dir` selects the backend's private state directory; its default matches the server. The layout command lists workspaces or returns one workspace's layout, revision and registered roots. It returns no drafts, transcripts or file contents. Mutations require an exact workspace ID and a closed JSON intent. Unknown fields refuse.

| Intent | Fields and effect |
| --- | --- |
| `show` | `rootId`, relative `path`, optional `paneId` and `preview`: reveal an existing text file, or its Markdown preview. |
| `split` | `paneId`, `axis` (`x` or `y`), and `view`: split with an exact existing [workspace tab](shared/api.ts) shape. |
| `focus` | `paneId`, optional `view`: select the pane or reveal the exact view without keyboard focus. |
| `resize` | `splitId`, integer `ratio` from 20 through 80: adjust a split. |
| `swap` | `splitId`: exchange its sibling branches without closing their views. |
| `notice` | Plain `text`, at most 512 characters: show a nonmodal notice. |

A conversation view identifies an existing agent or the current primary key and epoch. Control never resumes a different saved session. File views require an already registered root; the command does not register folders, supply document content, edit files or save drafts. It never sends model input, starts a host or process, changes execution settings, or exposes a shell endpoint. Existing tabs remain available.

The backend publishes owner-only `control.json` in its private state directory after listen. The CLI reads its loopback origin and separate credential without printing them. The credential rotates on every backend start; browser sign-in remains valid. Only control routes accept this credential. Browser cookies alone do not authorize agent requests, and the control credential does not authorize the ordinary browser API. Same-user access to the private credential grants presentation control; an optional actor label is supplied attribution, not verified agent authorship.

**Commands → Agent presentation control** switches control off for the workspace. Actions and their results appear in notices and the bottom status line with the supplied actor label. The bounded private lifecycle log records request identity, actor, workspace, action and result, not file bytes, notice text, drafts or credentials. Unavailable retained logging refuses admission.

Control requires one connected page for the workspace. It refuses ambiguous pages, stale revisions, unsafe geometry, pending navigation, active text selection, composition, menus, dialogs or resize. It also refuses a change that hides or changes the geometry of the active native editor, or changes the pane geometry of a conversation paused at an earlier reading position. Actions on unaffected panes remain available. Logical pane focus does not move the keyboard focus, caret, selection or reading position. Drafts and native Undo remain owned by their existing views.

[Control limits](shared/control.ts) include a 16 KiB request body, a burst of eight mutations with one restored per second, one outstanding request per workspace, eight globally, and a five-second execution deadline. Layout retains its normal pane and geometry limits. The CLI waits at most eight seconds. `applied` means the addressed page acknowledged the layout after persistence and placement. `refused` means application did not begin. `unconfirmed` means application or its acknowledgment is uncertain. The command never retries a mutation or restores an older layout: read the layout before a new intentional action. Reconnection and restart never replay control actions.

The equivalent loopback routes are `GET /api/control/layout`, `POST /api/control/requests`, and `GET /api/control/requests/:id`. They require the exact Origin and the control Bearer credential. A receipt GET with `?wait=1` waits for its result or execution deadline; at most one waiter per request and eight waiters globally are admitted. Control reads have a separate rate bucket with the ordinary HTTP limits, so their rate exhaustion does not consume the browser's bucket. The CLI handles discovery and this bounded wait without polling; direct callers must preserve the same credential and uncertainty rules.

## Security and limits

The server binds only `127.0.0.1`. It validates the exact Host and mutation Origin, rejects foreign fetch metadata, enables no CORS, and serves a fixed asset map: the page at `/`, `/style.css`, `/favicon.svg`, built browser modules under `/web/`, and the shared modules `/shared/api.js`, `/shared/version.js`, `/shared/files.js`, `/shared/health.js`, and `/shared/control.js`. Unknown routes return 404. Static asset requests retain these security checks but bypass API rate and active-request accounting. Static startup reads the retained browser build once, with a 2 MiB per-file bound, a 16 MiB total byte bound, and a 256-entry limit in dist/web; it refuses a missing required asset. Those bytes remain fixed until stop. The CLI instead publishes confirmed source generations under the development-update rules below.

A one-use launch capability expires by timestamp. The cookie is HttpOnly and SameSite=Strict; private `auth.json` retains only SHA-256 hashes, not raw session tokens or launch capabilities. A routine restart with the same private state preserves an authenticated browser session. Cookies issued by an in-memory-only backend lack a retained hash and require a fresh launch link after the first upgrade. Logout persists revocation before acknowledgment and closes that session's event streams, not admitted work; a later restart does not restore the revoked session. Invalid or unsafe authentication state refuses access rather than silently replacing it. Local HTTP does not provide TLS or Secure-cookie protection. A same-user process or browser-profile compromise remains outside this boundary. Another browser profile needs a deliberate new startup launch link.

CSP forbids inline scripts, evaluation, framing, objects, and foreign connections. Responses use no-store, nosniff, and no-referrer. Model, tool, custom, and diagnostic output is safe text or bounded structured data, never extension HTML. Transcript images are bounded raster data: PNG and JPEG only, at most 8 MiB compressed, 16,777,216 pixels, and 8192 pixels per edge; SVG, GIF, WebP, animated PNG, and signatures are omitted. Sensitive JSON keys and recognizable credential text are redacted in display projections. Authenticated file routes supply bounded text, drafts, explicit saves, directory pages, scoped live updates, and explicit tree operations only for canonical registered working folders. The UI exposes no arbitrary byte-download, shell, signal, or environment endpoint.

Resource bounds are defined in [shared/api.ts](shared/api.ts). They are UI implementation limits, not Pi limits. Oversized requests, exhausted reservations, unresolved-copy capacity, and incompatible protocols reject explicitly. Slow browser clients receive resync instructions instead of blocking process output. Request admission uses elapsed-time rate accounting, not periodic timers. Event streams are bounded independently per workspace; idle age/status displays do not tick.

The browser is not an offline draft ledger. A draft is saved only after the backend acknowledges its complete text, mode, and image references. A browser crash loses local edits and file bytes that never reached the backend. Ordinary execution does not become Durable merely because the browser survives refresh.

## On-demand health

Choose **Health** beside the bottom version identity to read an authenticated `GET /api/health` snapshot. The dialog shows backend PID, start time, uptime, supervisor replacements, serving identity, worker/RPC availability, build state, RSS, and active API request capacity. **Refresh health** requests another snapshot; the closed page and open dialog do not poll. The read does not scan the agent store, select a conversation, or change focus or drafts. Local worker availability is not remote-host readiness. Missing or invalid health facts produce an explicit unavailable result, not a healthy default. Health remains separate from browser connection recovery.

## State and delivery

The backend owns private atomic files beneath `--state-dir`:

- `instance.json`: installation identity and state format.
- `lock.json`: exclusive UI state-root ownership; a live or unknown owner refuses another backend.
- `lock-recovery.json`: persistent macOS kernel-lock guard, held for the state owner's lifetime. Its presence alone does not indicate a live owner; do not delete or replace it.
- `auth.json`: bounded durable session hashes; only an acknowledged logout revokes that session across restart.
- `lifecycle.log`: bounded redacted lifecycle records, not an input or provider-output archive.
- `primaries.json`: saved keys, project paths, and session metadata, never a live PID authority after restart.
- `workspaces/`: selection, agent observation visibility, sidebar visibility and width, appearance, Enter-send preference, pane tree (conversation and file tabs, active tab, focused leaf, split axes and ratios), file reading positions, and revisions.
- `files.json`: canonical root identities and separately revisioned workspace browse folders. Old roots remain available to retained file tabs.
- `file-drafts.json`: current acknowledged file drafts and compact clean records in strict `ui.file-drafts/2` format. Each record retains its revision, base disk revision, and encoding information. Explicit successful Save alone releases that file's text payload. Closing a view never deletes a draft.
- `targets/`: separate epoch/agent drafts, reading anchors, and expansion preferences.
- `operations/`: issued keys, dispatch digests, receipts, and unresolved or retained complete input copies.

Image bytes remain in private content-addressed storage. Authenticated routes bind each upload and preview to the exact workspace and recipient; browser snapshots carry metadata, not image bytes.

Saved drafts and captured inputs require explicit image arrays, including empty arrays for text-only input. A record without this metadata is refused and produces a notice; its saved file remains unchanged. Valid text drafts and unrelated queue recovery remain available. Unknown image ownership disables image uploads and cleanup, preserving saved bytes. Queue recovery never rewrites a refused operation at the same identity.

Directories are private and files are owner-only. Serialized mutations use compare-and-set revisions, adjacent exclusive temporary files, file sync, atomic rename, and directory sync before acknowledgment. There is no multi-file filesystem transaction. Do not remove a live or unknown state lock. Registry startup recovers a lock only when the existing local host/PID checks prove its recorded owner dead. A foreign host, unknown owner, or live PID refuses startup; age alone grants no recovery. A hostname change prevents same-host proof and refuses automatic recovery. Corrupt or partial owner records produce an explicit unavailable result and remain unchanged. A synced complete owner record publishes exclusively before initialization. The macOS kernel guard remains held through state writes and token-checked release; process death releases the kernel lock without deletion of its inode. This never permits removal of an Agent writer claim.

Operation reservations precede effects. A repeated issued key with the same body returns the retained state; a changed body or target conflicts. Unknown or expired keys never create work. The backend persists dispatch intent before an external write. Missing admission evidence becomes uncertain, not automatically replayed. Definite refusals retain the draft. Admission cleanup clears only the submitted revision, never newer edits. Handled-image responses retain the draft because they do not confirm image delivery.

Recovery copies preserve the exact recipient, text, delivery mode, and ordered image metadata. Lists contain bounded previews; each review reads the complete saved copy by its operation ID. Copy exports text only. Restore atomically replaces that recipient's whole draft at the displayed revision and never sends. Discard deletes only the local copy and does not cancel work or prove non-admission. Older-epoch targets remain discoverable through the backend target index. Saved-draft rows show the exact bounded prefix of that target’s acknowledged draft, with an explicit shortened-preview notice when needed. Names, snippets, and saved-message counts stay separate; the target detail still supplies the exact complete draft.

The browser reduces stream events immediately. It coalesces transcript source construction and indexing into the existing animation frame, using the latest state rather than rebuilding for every delta. Editor and input availability updates remain immediate. Deferred sources prevent stale Copy, source and reference actions; direct target changes discard pending transcript work. Unchanged entries retain their nodes.

The SSE journal is memory-only. Each backend run has a new boot ID; ordered replay or snapshot resync reconciles browser state. Transcript projections are bounded memory windows, not another permanent session archive. Large ordinary RPC records decode and project off the HTTP event loop. Saved history uses a worker-owned byte-offset index; `get_entries {since: lastIndexedEntryId}` supplies the authoritative active leaf without repeatedly transferring the full branch. Earlier pages read and project bounded records from that branch. Output controls load one bounded protected-text page at a time, with Previous, Next, and Start over controls rather than accumulating the full output in the DOM. Transcript images load only through an authenticated same-origin route keyed by the exact primary key and epoch, or the native agent identity, together with the entry, message, and part indexes and the SHA-256 digest. Event frames carry no image bytes or base64 payloads; the route serves each image on demand, allows two image reads at a time, and answers a third with an explicit capacity error. The browser hydrates history when the selected primary becomes ready and cancels stale startup requests. Empty startup history does not claim the resumed pagination boundary: the first populated page exposes Earlier when older entries exist, and later tail refreshes preserve progress through earlier pages, including exhaustion. Unavailable sources, invalid anchors, and exceeded source limits return visible errors.

## Files

Files shares the existing navigation width and section disclosure. The Working folder control is its only folder selector. The selected primary's directory supplies the initial root, otherwise the launch directory does. Later folder choices remain independent of conversation focus. Folder disclosure never selects, starts, observes, or sends to a conversation. A file selection displays its content directly in the focused main pane. File and conversation tabs share moves, closure, splits and resizing. Same-file selection reuses its tab. Plain browsing replaces one transient file view per pane, never a modified, kept, or deliberately split/moved view. Double-click a file or tab, or choose **Keep tab** in its existing menu, to retain it. Restored views are retained. **Close others** and **Close all** close views without deleting acknowledged drafts. File views have no tab-count cap; only conversation tabs count toward conversation admission. Existing layout and request byte bounds still apply. Same-name file captions use useful directory suffixes instead of serialized identity. Identical relative paths across roots add a short unique root-identity tail. Source ownership is separate from view position and pane ownership. Old file tabs keep their registered roots when the browse folder changes.

Directories load lazily on disclosure, with folders first and deterministic name order. Hidden entries remain visible except version-control internals. Up/Down/Home/End move among visible supported entries; Left collapses or selects a parent; Right expands or enters an actual child; Enter/Space selects a file or toggles a directory; Escape returns to the focused view. Unsupported entries are inert. Refresh files starts a new listing; More files continues a bounded page. Incomplete coverage never claims an empty folder.

Live updates watch only disclosed directories and parents needed by open files, including retained roots other than the browse folder. Shared nonrecursive handles filter undisclosed parents to their requested filenames. The backend coalesces filesystem hints into scoped `files.changed` events; unknown filenames or an exceeded event budget request a scoped rescan. Scope replacement supplies an initial invalidation, and newly registered handles schedule one coalesced baseline rescan. Neither event is a watcher-readiness guarantee. The browser updates disclosed listings and open documents through bounded queues, preserving inline inputs, disclosure, focus and reading positions. An in-flight path receives at most one coalesced follow-up. Tree repaint and path remap retain each row's child nodes. No recursive whole-root watch or polling fallback exists.

A clean open document adopts changed disk source in place with its native selection clamped to the new text. Modified or unacknowledged text remains untouched; differing disk source shows a conflict. The document keeps the owned text's original editing base separate from observed disk state, including before its first acknowledgment. Late passive reads never replace newer text or base from a successful Save or deliberate re-read. A missing source retains its draft and a quiet missing state. A watcher error, replaced directory identity, worker loss or exceeded scope capacity reports live updates unavailable in the bottom status line. **Refresh files** remains an explicit listing action without a retry loop. Each page owns its scope through its live update stream. The backend watches the union of those scopes within each workspace. Stream departure releases only that page; reconnect starts without retained scope and establishes a fresh scope and read baseline. Scope limits do not become a file-tab admission cap.

The tree's context menu offers **New file**, **New folder**, **Rename**, **Move**, and **Move to Trash**. Right-click, the context-menu key or Shift+F10 opens it; empty tree space permits creation at the root. With tree focus, F2 renames, Cmd/Ctrl+N creates a file, Cmd/Ctrl+Shift+N creates a folder, and Delete or Cmd+Backspace requests Trash. New and renamed entries use an inline name field; Move uses a destination path relative to the working folder. Enter submits, Escape cancels, and IME composition never submits. A refused name stays editable without changing the document draft. A new file opens in the originating pane ready to type after its name field closes and its source loads. If focus or the pane changes while creation is pending, completion does not take focus or select the file in another pane. Native file focus selects its current pane and updates the bottom status line without moving the editor or its controls. Trash uses one worded confirmation and never silently closes views or discards drafts.

Creation, Rename and Move refuse an existing destination, saved destination state, destination-prefix document in any retained workspace layout, or destination-prefix open file in any registered page watch scope before the effect. Saved state includes compact records without text: their revisions protect against stale writes, so saved names are not automatically reclaimed after Trash. Choose another name for these entries. Rename and Move stay within one registered root and filesystem. Identity refusal ignores source/preview kind and excludes documents actually in the moved source set. It does not choose a winning draft, view or position. Closed or not-yet-published unacknowledged browser identities remain outside server visibility. On a local identity collision, the moved source remains canonical. A clean unused destination owner without native views is disposed. Destination owners with local work or native views stay distinct, retained and read-only. **Review retained draft** in the bottom status line exposes selectable text through the existing modal, including closed owners. Close keeps the retained work and unload protection; only confirmed **Discard retained draft** removes that retained owner, never the canonical source or disk bytes. Retained owners stop future reads, writes, watch/position traffic and development updates; late answers never release their text. Unacknowledged retained text remains browser-local and is still at risk in a browser crash. The browser drains its owned draft, position and selection writes before its move. Successful explicit moves map the exact path or directory prefix across retained draft records, source and Markdown preview owners, tabs, active keys and positions. The browser rekeys the same native views before workspace repaint without assigning source text. Syntax decoration and accessible names follow the new extension. A confirmed move clears missing/error state from the old path without clearing original-base conflicts or prior draft/Save refusals. The backend advances all workspace revisions and publishes the move mapping before workspace changes; stale old-identity draft or selection writes refuse instead of recreating ghost records or tabs. External rename hints never invent a path pairing: the old view becomes missing with its draft retained, and the new tree entry appears.

Typing edits file source directly in a native textarea, without an edit-mode gate. Native selection, caret, scroll and undo stay with the stable source view across pane switches, splits and moves. Syntax colors use the existing in-house range tokenizer for TypeScript, JavaScript, JSON, Markdown, CSS, HTML, shell, YAML, TOML and Python. Unknown languages and decoration beyond its local bounds remain plain text. Color decoration never changes native source, selection or undo.

**Save** beside the view and Cmd/Ctrl+S explicitly save the file. Cmd/Ctrl+Z remains native undo; Escape never discards text. A quiet tab marker identifies modified source and preview views. Draft persistence, save, conflict and failure facts appear in the bottom status line. Acknowledgments never assign the textarea value; typing during a save preserves newer text and rebases its later draft acknowledgment on the saved disk revision. A reopened source view temporarily stays read-only while its owner drains the draft and refreshes disk state.

Markdown source and **Markdown preview** are distinct views of one file owner. The existing tab menu supplies the alternate view; **File source** returns to the source view. Both views fit the shared pane splits. Preview reflects acknowledged draft text through the existing sanitized renderer for headings, lists, tables, quotes and code. Prose stays left-aligned within a bounded reading column; code and tables retain useful width and local scrolling. Raw HTML remains text and remote images do not load. Only absolute HTTP(S) links are active, with a separate browser tab and `noopener noreferrer`; relative, fragment, file, data and script links remain inert.

The disk source retains exact UTF-8, BOM, line endings and final-newline state. Native source excludes the initial BOM and uses LF separators. Save restores the original BOM and uniform LF or CRLF convention. Mixed separators, lone carriage returns, invalid UTF-8, unpaired surrogate edits and unsupported binary bytes refuse writes. Empty files, tabs, Unicode and final-newline absence round-trip. Missing, binary, oversized, unsafe and denied content each has one accurate quiet state.

Worker acknowledgment follows atomic private draft persistence with a compare-and-set revision and a base disk revision. A first draft with no retained record must match the current disk revision and encoding; a delayed write with a different old base or encoding refuses without seeding the new identity. An already acknowledged draft still accepts further edits against its retained base after an external disk change, while explicit Save refuses that conflict. A `file_changed` draft refusal immediately exposes the existing conflict and re-read controls without waiting for a filesystem event. Reload and view closure retain acknowledged unsaved drafts. The browser's existing unload guard also protects file input before acknowledgment, pending file writes, draft failures, and failed Save acknowledgments. A read-only error with no unacknowledged text does not trigger that guard. Failed Save remains guarded until a successful Save or authoritative disk/draft refresh or deliberate re-read resolves it. A browser crash still puts local edits that never reached the backend at risk. Successful explicit Save replaces only that file's persistent text with compact revision/base/encoding metadata; no unsaved acknowledged draft is evicted. A restored draft whose base differs from disk shows a conflict. An external disk change refuses Save without deleting the draft. **Re-read file** deliberately replaces the draft with current disk source; **Keep editing** returns focus without permission to overwrite. No automatic merge or force-save exists.

The authenticated root preference routes are GET/PUT `/api/workspaces/:id/files/root`. The path workspace is authoritative; a supplied workspace query must match that path. Directory and text reads use GET `/api/files/roots/:rootId/directory` and `/api/files/roots/:rootId/text`, with an explicit workspace and relative path. GET `/api/files/roots/:rootId/draft` returns the current revision and acknowledged draft, or `draft:null` for a clean saved record. A clean record retains its nonzero revision for later compare-and-set edits. PUT on the draft route requires `expectedRevision`, `base`, `encoding`, and `text`. PUT on the text route requires only the acknowledged `expectedRevision` and explicitly saves that captured draft. A save response still contains current disk source and the full rebased draft. Repeated Save of a clean record checks its base against current disk state without rewriting the file. Directory queries additionally accept bounded limit/cursor fields. Unknown or repeated fields and unsupported verbs are refused. File mutations receive their own escaped-source JSON byte bound; other request bounds stay unchanged. GET `/api/workspaces/:id/files/watch?clientId=:uuid` reads that page's status. PUT on the watch route replaces `{clientId,roots:[{rootId,directories,files}]}`; an empty roots array releases only that page's scope. A page generates one client ID, shares it with `/api/events?workspace=:id&after=:cursor&clientId=:uuid`, and keeps it across reconnects and workspace changes. Watch requests require that same live workspace/session/client binding. Each stream `ready` causes a full scope PUT. Duplicate same-page streams replace the old stream and release its scope before the new one becomes ready; unrelated event clients need no file scope. File operations run in one serialized worker. [shared/api.ts](shared/api.ts) defines `fileTextBytes`, `fileDirectoryEntries`, `fileScanBytes`, `filePageItems`, `fileResponseBytes`, `pathChars`, `filePending` and `fileReadMs`; component and private root-state bounds remain in the file-access/state modules. Browser listing and document-read concurrency stay bounded in [web/files-tree.ts](web/files-tree.ts) and [web/files-views.ts](web/files-views.ts). A timed-out or canceled dispatched read retains admission until it actually settles. Browser departure does not abandon a dispatched file mutation. A mutation deadline instead fails closed, invalidates file identities, and requests worker termination without waiting for blocked I/O. A late reply cannot publish a move or admit another file mutation. Move and create admission use the workspace queue, but their external file waits do not hold it; unrelated state work continues. A pending move refuses layout and file-position writes, while metadata-only workspace updates remain available. Shutdown waits for actual worker exit before releasing the private state lock. If a page scope cannot be released, the file service stops rather than silently retaining an unreachable live scope. The private draft file uses the file-response byte bound, with no draft-count cap; Save reserves bounded revision metadata space before any disk write. The root-selection state retains its existing byte bound.

Move and Trash require macOS. [server/file-operations.mts](server/file-operations.mts) uses the system `osascript` utility with JavaScript for Automation and Foundation, not Finder or an automation target. Native paths are argv values, never interpolated executable code. Darwin `renamex_np(RENAME_EXCL)` enforces destination non-overwrite inside the native syscall; a precheck or ordinary rename is not its substitute. Foundation moves Delete targets to the native recoverable Trash instead of unlinking them. Its Trash location belongs to the account and volume; a private HOME does not isolate it. Native helper execution and output are bounded, and a lost helper acknowledgment reports no confirmation rather than permission to replay. No runtime package or compiled helper is added. Filesystem effect, draft persistence and workspace publication are not one atomic transaction. Missing or malformed native acknowledgment, a mutation deadline, and any failure after a confirmed filesystem effect invalidate file identities and refuse further file/layout actions. This includes identity checks, directory sync, draft persistence, watch remapping and workspace publication. These outcomes require a backend restart and inspection of both paths, not a retry. Worker termination is not proof that a native filesystem effect was canceled or undone.

Canonical registration records root device/inode identity. Reads reject traversal, ambiguous encoded separators, version-control internals, symlinks beneath a root, multiply linked files and special files. A nofollow, nonblocking leaf descriptor must match the checked identity; before/after metadata and component revalidation reject detected changes. Save accepts only an existing regular singly linked file whose size, mtime and digest equal its draft's base revision. It writes an exclusive same-directory temporary file, preserves mode, syncs it, rechecks file revision and root components, atomically renames it and syncs the directory. It never recreates a missing target. A lost Save acknowledgment never triggers write replay; reload establishes current disk source and the persisted draft revision. The final revision check and rename are separate operations: an external write in that interval remains a time-of-check to time-of-write race. A deliberately chosen folder alias is resolved at registration. These checks do not guarantee containment against a hostile process under the same user that swaps an ancestor out and back between checks. Node on macOS supplies no descriptor-relative openat directory walk. The native move/Trash utility does not supply that stronger path-walk boundary.

## Implementation choices

Workspace theme, agent observation visibility, sidebar visibility, sidebar width, and conversation layout use workspace revisions. Card expansion uses a separate target presentation revision so a disclosure cannot conflict with draft text. Reading positions use stable IDs and offsets, not DOM indices. Opaque target keys name private files; raw agent identities never become filenames. Conversation operation and target mutation transactions serialize consistency checks; their external RPC/native waits occur outside that queue. File move admission and identity publication use workspace serialization; the external filesystem wait stays outside that queue. Browser rendering coalesces through animation frames, not a streaming debounce.

# Web harness

A local browser interface for ordinary Pi conversations and retained Durable agents. The terminal harness remains independent: the UI does not load as a Pi extension and imports no extension source. Its agent links use the public package-level [transport entrypoint](../transport/index.ts). Stop this process to return to terminal-only use.

## Start

```sh
npm run ui
```

This builds the checkout's browser modules, starts the selected sealed release for the current directory, and opens the local URL in the default browser. Pass flags after `--`, for example `npm run ui -- --cwd <project-directory> --state-dir <selected-root>`. For manual browser startup, use `npm run ui:start -- --cwd <project-directory> --state-dir <selected-root>` and open the printed local URL yourself. Both commands use `ui/server/main.mts`. With an existing release selection, they start that snapshot, not the changed checkout. Without a selection, the launcher stages the checkout first; staging requires clean committed source and browser assets emitted after that source changed. `npm run ui:build` only emits checkout assets. Use the explicit stage and switch commands below to advance a running release. Press Ctrl-C to stop the supervisor, browser links, and owned primary processes, not independent Durable agent work. Open the plain loopback address in any browser profile; no sign-in, launch secret or session cookie is required. Starting a Primary or opening a saved session is an explicit action; backend startup and tab refresh never create a primary or send model input. First use shows saved sessions inline for the launch directory; a deliberate switch uses the same list in a dialog. Passive working-folder text sits beside a named folder SVG control that opens the anchored **Working folder** chooser. Every project label uses the shortest path suffix unique among the listed directories; repeated sessions in the same directory share that label. A leading slash identifies a complete directory when it is also a suffix of another path. Full path data remains unchanged in titles, descriptions, and actions. The menu loads recent projects automatically and retains explicit refresh and pagination. A listed folder selection changes only the workspace's browse folder; it does not select or start a Primary or show saved sessions. **Other folder…** opens the explicit directory form and changes the same browse folder. File selection displays content in the focused main pane without changing the retained conversation selection. **Sessions** focuses the inline list on first use and uses the same chooser in a dialog only when a conversation occupies the main region. **Session file…** reveals an exact JSONL path without removing the selected project, search, or list.

Flags:

| Flag | Meaning |
| --- | --- |
| `--cwd` | Launch-directory suggestion; the directory must exist. |
| `--port` | Local TCP port, default `4318`; `0` requests an assigned port. |
| `--pi` | Pi executable, default `pi` on PATH. Arguments are supplied as an array, without a shell. |
| `--state-dir` | Private UI state directory; default `<agentDir>/ui`. |
| `--open` | Open the local URL in the default browser through the macOS `open` command after the backend listens. A failed open leaves the backend running and prints the URL. |
| `--dev-reload` | Source-watch option for direct backend development. Sealed-release supervision disables it. |

The backend uses native Node TypeScript stripping; runtime files contain only erasable TypeScript. Browser modules compile through `tsc` to `dist/web`; generated output is ignored. No bundler, framework, transpilation loader, or new runtime package is required.

`PI_CODING_AGENT_DIR` selects the Pi agent directory; otherwise the usual home-relative Pi directory applies. `PI_AGENT_SESSIONS_DIR` selects the retained agent store; otherwise it is `<agentDir>/agent-sessions`.

## Appearance and user stylesheet

**Appearance** offers System, Dark and Light. Under it, one quiet line says "Your stylesheet is applied." or "Add your own stylesheet with ui.userStylesheet in harness.json." The line reflects the loaded page: the server links the stylesheet into the page only when the file is usable at page load.

One setting in the `ui` section of `<agentDir>/harness.json` selects a user stylesheet, following the [extension configuration contract](../docs/conventions/extension-config.md). The UI reads its section with its own code in [server/settings.mts](server/settings.mts); it publishes no settings event, so **Health** is its inspection view.

| Key | Environment | Type | Default | Constraints | Description |
|---|---|---|---|---|---|
| `userStylesheet` | `PI_UI_USER_STYLESHEET` | path | unset | nonblank, at most 4096 characters; a relative path resolves against the agent directory | Stylesheet served after the base styles. |

Behavior:

- The server reads the file on each page load and each `/user.css` request, and never keeps a copy. A browser reload applies an edit. There is no watcher.
- The page links `/user.css` after the base stylesheet only when the file is a readable regular file of UTF-8 text, at most 256 KiB. The route answers `text/css` with `Cache-Control: no-cache`. Otherwise the page has no link and no banner, and the route is not found.
- **Health** shows a **User stylesheet** row with one fixed word: Not configured, Applied, File not found, File too large, File not readable or Setting invalid. It shows no path and no error text.
- The content security policy is unchanged, so the stylesheet cannot load remote resources.
- The AA contrast tests cover the shipped color sets only. A user stylesheet answers for its own contrast.

Token rules in the base stylesheet have zero specificity, so a user rule wins by order alone:

```css
/* both modes */
:root { --canvas: #101214; }
/* one mode */
:root[data-appearance=dark] { --accent: #e0af68; }
:root[data-appearance=light] { --accent: #8c5a00; }
```

A one-mode rule applies when that mode is chosen explicitly. Under System, the explicit rules do not match; use `@media (prefers-color-scheme: dark)` or `(prefers-color-scheme: light)` around a `:root[data-appearance=system]` rule.

|---|---|
| Surfaces | `--canvas` page, `--side` sidebar, tab bar, status line and input turns, `--raised` hovered and current rows, `--code` code blocks and inline code, `--run-bg`, `--ok-bg` and `--err-bg` tinted state panels |
| Text | `--fg` primary, `--muted` secondary, `--dim` metadata |
| States | `--success`, `--error`, `--warning`, `--info` |
| Link and accent | `--link` links in content, `--accent` focus, active tab and input rail |
| Rule and edge | `--edge` control borders and neutral marks, `--rule` hairlines, `--backdrop` dialog dimming, `--shadow` floating surfaces |
| Syntax | `--syntax-keyword`, `--syntax-string`, `--syntax-number`, `--syntax-comment`, `--syntax-fn`, `--syntax-type`, `--syntax-property`, `--syntax-operator`, `--syntax-punct`; Markdown source highlighting uses `--md-heading`, `--md-em`, `--md-strong`, `--md-link`, `--md-code` and `--md-marker` |

| Type and space | `--sans`, `--mono`, `--s1` to `--s4`, `--gutter` |

## Ownership and terminal return

Each explicitly opened ordinary primary has a retained key and conversation epoch. A raw owner in the supervisor holds its RPC pipes and detached process group. Refresh, tab close, and backend detachment do not close those pipes. A replacement backend attaches to the existing process; it does not spawn a substitute or resend input. Drafts and actions capture the exact key/epoch or Durable identity; a session replacement rejects old-epoch actions. A primary's accepted input is not proof of a completed model answer. Execution becomes idle on `agent_settled`. Completed manual compaction uses an authoritative state refresh guarded by the conversation epoch, lifecycle, and activity revision; newer activity takes precedence.

Use **Continue in terminal** to release an ordinary primary:

1. Choose whether to wait for accepted work or abort it, and whether to clear its queue.
2. The backend freezes admission, retains cleared-queue recovery copies, and verifies a saved file.
3. The backend requests deliberate close through the owner, which closes RPC stdin and waits for the child to exit.
4. Only after exit does it return the quoted project and `pi --session` command.

An empty, unpersisted session has no resume command. A blocked exit has no successful handoff command. The UI never launches a terminal, takes another process's PID, or kills a writer to claim the file.

A failed transport or failed initialization does not prove child exit. Such a child still owns its saved file and primary capacity. If shutdown cannot confirm exit, the backend retains its state-root lock. After verified exit, it completes local state cleanup without a takeover or process signal. Pending primary opens stop before shutdown releases state ownership.

After you exit Pi in the terminal, choose **Resume here** in **Ready for terminal** to reopen that exact saved conversation directly. The action uses the handoff receipt's working folder and saved file without a list refresh, search, or another confirmation. **Open session…** remains available to choose a different conversation. Neither the handoff result nor terminal exit starts a browser primary automatically.

Opening a saved session is itself the deliberate resume action: **Resume here**, or the click or Enter on a saved row, starts the primary on that exact file with no separate confirmation step. After backend replacement, a live primary reattaches through the raw owner. When no live owned primary remains, an explicit open of the same verified saved conversation reuses its retained primary key and conversation epoch. Its workspace keeps the acknowledged draft, reading position and presentation. Explicit Resume selects the returned Primary tab; ordinary refresh preserves the current layout. The server's selection of the returned session does not cancel that explicit action. A canceled picker or later workspace, pane or conversation choice prevents delayed selection and focus. Other input during Resume suppresses late composer focus without canceling the admitted selection. Recovery requires both the canonical file and saved-session identity to match; ambiguous or changed identities are refused without transferring state. Restart alone starts no primary and replays no input or uncertain operation. Pi exposes no public saved-file writer lock or owner query, so the backend cannot detect a terminal or other external writer; close that writer yourself before you open the file here. The backend rejects duplicate canonical files within its own registry, refuses a file another backend primary already writes, and selects an already open backend session instead of opening it again. Each active process keeps its own in-memory branch; the UI does not read later writes from another active process. Concurrent writers can create separate branches. Stop both writers before reopening the saved session. Inspect and select branches with Pi’s `/tree` command; this UI does not merge branches. There is no automatic terminal-to-browser attachment.

### Convert saved context to Durable

The session picker shows named registered ordinary sessions across folders beside
native Durable conversations. Its project list also retains archived ordinary
sessions. Public primary metadata corrects unavailable names only after exact
saved-file and session-ID matching; registration is not proof of live idle state.
Discovery limits and unavailable records remain visible. **Search sessions** filters
all loaded groups: Durable conversations, registered ordinary sessions, and ordinary
sessions in the working folder. Arrow navigation follows their visible order; Enter
activates the focused row, or the first match from the search field. Conversion
remains a separate action. A query reads no new catalog or session page. Each group
keeps its own empty or incomplete state, and registered paths stay suppressed in
the folder group even when filtered out. One footer outside the scrolling results
counts the presented session rows across all groups, excluding other controls and
backend totals. Group-local List details disclosures retain loaded counts, known
totals, omissions, uncertain titles, and saved-read times. A single **Partial list**
note sits in the dialog footer beside the loaded count while any group is incomplete; loading, saved and failed states remain explicit.
More saved sessions stays within the folder group. The heading, search and global
count stay available while results scroll. Conversion explains its saved-context
copy beside that action rather than in a permanent group paragraph.

Every ordinary row has one **Convert to Durable** action. This creates a new
native identity with the same actual name. Selection follows the captured picker,
workspace and pane choice; cancellation or a later choice prevents late selection
without undoing admitted creation. The
original file stays unchanged. It does not resume an ordinary session, submit the
transcript as a new prompt, or transfer the coordinator role. The source is a
complete unchanged saved snapshot, projected through public Pi helpers at the
final persisted leaf with compaction and context edits applied. Unpersisted live
selection, queued or in-flight work, system prompts, extension runtime state and
future provider transformations are excluded.

Capture refuses incomplete, malformed, cyclic, changed or oversized input. Its
limits are documented in [saved context creation](../docs/agent-host-contract.md#saved-context-creation).
The action retains its operation key across an unconfirmed response. A lost
acknowledgment stays uncertain and requires inspection, not automatic replay.
The receipt returns the exact new identity and name. Ordinary owner reload and a
live ordinary context endpoint are not prerequisites. Conversion does not stop or
replace the source process.

Startup extension errors are initialization warnings with bounded text. Their presence or absence does not establish exclusive session ownership.

## Supervisor and recovery

The supervisor and raw owner run from sealed files. Their runtime import closure uses Node builtins and local owner, protocol, diagnostic, and release-control modules. Registry, StateStore, display projections, agent transport, image preparation, and browser build code remain outside that closure in the replaceable backend or staging process. Detached Pi process groups stay outside backend group cleanup.

The supervisor preserves the selected TCP port across backend replacement, including an initially assigned port. It confirms cleanup of the recorded backend group before replacement. Repeated abnormal exits exhaust a rolling crash budget. At exhaustion, the supervisor attempts a distinct retained last-good release once; otherwise it leaves the backend unavailable while the owner, Pi processes, and release-control socket remain available. Planned switches do not consume that crash budget. Unconfirmed backend cleanup blocks replacement rather than taking another process's resources. The deadlines and crash policy are defined in [server/supervisor.mts](server/supervisor.mts).

Backend detachment and whole-stop are different operations. A planned detach checks native reconstruction through complete raw capture, fences in-flight HTTP effects, then closes backend streams and adapters, saves primary metadata, and releases the backend state-root lock. It does not clear Pi queues, cancel dialogs, abort execution, or close Pi stdin. A fatal backend condition attempts this detach path before a bounded nonzero exit; the supervisor retains raw ownership.

Whole-stop asks the attached backend to close its primaries deliberately. Queue recovery and confirmed writer exit precede successful completion. If no backend remains, the owner reserves private recovery storage, retains cleared queue responses, cancels visible dialogs, requests abort, and closes stdin. Uncertain recovery or exit blocks clean shutdown instead of force-killing Pi. A release-control stop receipt acknowledges the request, not completed shutdown. Status distinguishes stopping, blocked shutdown, and stopped. A shutdown deadline retains writer ownership and the pending recovery sequence; a later stop waits on that sequence instead of repeating its effects. No restart replays prompts or uncertain effects. An unconfirmed owned primary is quarantined per primary: automated close refuses its queue, dialog, abort and EOF effects while its writer is alive, and a verified exit still permits normal cleanup.

On attachment, the backend reads native state and history around a bounded owner capture. It joins completed records, the active assistant delta tape, supplied tool partials, extension state, and original dialog deadlines, then releases the ordered suffix. Missing capture coverage blocks a planned switch; crash attachment exposes incomplete presentation instead of inventing missing partial output. The owner retains command outcomes until durable backend acknowledgment. A completed session transition advances the epoch only after a confirmed uncanceled RPC result; receipt lookup and acknowledgment keep the operation's original epoch. Stale-epoch effects refuse. A retained metadata epoch that disagrees with the owner is reconciled per primary. Per primary, the backend adopts an owner-advanced epoch, advances the owner to retained metadata whose refreshed native identity matches, or accepts only an exact completed transition receipt at the original epoch; it never rolls an epoch down or redispatches the command. Without one of those proofs, that primary stays failed with input disabled and its writer retained while other primaries start.

Cancellation of a live history read releases only that read request. The host connection and native conversation remain available.

Protocol-loss recovery is capability-gated. After a verified fresh native refresh of state, resources and full active-branch history, the backend sends the optional resynchronize action to an owner that advertises capture-resynchronize/1 before capture finish. Protocol recovery restores owner admission; incomplete capture coverage still disables backend input. Dropped raw records, unknown dialogs and active-message overflow keep their own loss reasons until a confirmed epoch reset or their observed settlement, so a capture can report synchronized with incomplete coverage. Pi does not expose silently canceled pending dialogs, and pipe delivery does not prove consumption.

A failed file or agent worker reports unavailable while its adapter attempts recovery. Each adapter permits at most three replacement workers over its lifetime, without idle retry polling. Recovery requires confirmed startup before safe watch scopes or confirmed agent observations return. It does not repeat pending mutations, input, aborts, or configuration. Retained admission receipts and recovery copies remain authoritative. An uncertain file effect permanently disables file-worker recovery for that backend run and blocks file identities; inspect the affected paths before a deliberate backend restart. Worker exit never proves that a filesystem effect was canceled.

The private `lifecycle.log` retains a recent window of redacted startup, replacement, shutdown-request, fatal-class, unavailable and control records. An `unavailable` record names the reason when the agent catalog scan fails or its refresh is refused (once per distinct reason), and when a primary stops without a request or fails to start, with the exit code and signal when the process reported them; the same line goes to the backend's standard error. Its limits are 64 KiB, 128 records, and 512 characters per detail, with at most 64 control records in that window. Oldest control records leave first when their limit is reached; the total byte and record limits still apply to every event kind. One coalesced writer closes during backend teardown. The supervisor discards oversized diagnostic lines, redacts complete lines before terminal relay, and caps relayed diagnostics at 64 KiB for its lifetime. Input bodies, credentials and raw error stacks do not belong in retained logs. Log failure does not grant state ownership or turn a failed operation into success.

## Snapshot releases and rollback

`node ui/cli/release.mts prune --state-dir <private-state> [--keep-release <full-release-id>]` frees one descriptor slot for the next stage. It retires only the oldest unprotected catalog entries. Current, last-good, failed, the running owner's source release, and explicitly retained releases remain protected. Retention refuses a changing selection or owner. Sealed snapshot files and dependency directories remain intact for loaded code and explicit bindings; this command reclaims descriptor capacity, not snapshot byte capacity.

Build browser assets and commit the intended UI, transport, and package source before staging. Staging first checks the emitted browser modules: every file the browser compiler reads (the `.ts` files its `tsconfig.json` includes plus the relative modules they import) needs an emitted `ui/dist` file that is at least as new as the source file and the `tsconfig.json`. A missing or older emitted file refuses with "Browser assets are not built from this source. Run npm run ui:build." Staging never runs the compiler. The check reads the checkout; the copy does not preserve file times, so it is not repeated on the staged files. A checkout or rebase that rewrites a source file also requires a rebuild. Staging copies source and runtime dependencies into real files beneath the selected state root; it refuses symlinks, unsupported files, changed bytes, incompatible metadata, and exhausted capacity. It does not build assets, stop the running backend, or select the candidate. The staging parser requires the explicit Node flag shown here:

```sh
node --experimental-vm-modules ui/cli/release.mts stage --source <checkout> --state-dir <selected-root>
node ui/cli/release.mts status --state-dir <selected-root>
node ui/cli/release.mts switch --state-dir <selected-root> --release <full-release-id>
node ui/cli/release.mts rollback --state-dir <selected-root>
node ui/cli/release.mts stop --state-dir <selected-root>
```

Staging also reads the newest 30 commits of the checkout (identity and first line of the message, control characters removed, each subject cut at 120 characters, the whole list kept within 8 KiB of encoded page identity) with one `git log` and stores them as an optional `recent` list in the release manifest. Releases staged without it, and manifests with an invalid list, simply have none. A checkout run reads the same list at server start. The list rides in the page's `ui-identity` metadata; no route and no runtime dependency are added.

**Update notice.** Each tab remembers in `sessionStorage` the release it showed last. A tab's first load shows nothing. When a page shows a different release, one footer item beside the version reads "Updated to 9b278ce4" with **Details** and **Dismiss**; a reload of the same release keeps it until it is dismissed, and the next update shows it again. Details lists the commits kept in the new release that are newer than the earlier one, newest first, at most 20, then "N more"; **Copy changes** holds every kept subject. When the earlier release is not in the kept list (or the release has none), Details says so and shows the two full identities. Subjects are text only. While an update waits, the footer says why: "Update waits while you type", "…while you compose text", "…while text is selected", "…while you resize a pane", "…while a dialog is open", "…while the connection is offline", "…while a draft conflict is open", or "…until a sent message is confirmed"; a cause without a sentence keeps "Update paused".

Use the same selected root for launch and control. Stage returns a full release identity; switch requires that complete identity. Status reads the live private control socket, or the retained selection when no socket listens. A selected root whose socket path exceeds the platform limit refuses explicitly. Release control remains separate from the browser presentation-control API.

Switch verifies the sealed candidate and its owner protocol, starts a candidate process, and checks its manifest, assets, and read-only live-owner handshake. This prewarm does not open Registry or hydrate history. After the active backend confirms its capture/page checks and HTTP fence, it detaches and exits. The candidate then acquires backend state ownership, attaches primaries, and listens on the retained port. Only confirmed readiness updates the selected release and last-good identity. A pre-detach failure cancels the fence; a failure after detachment attempts the prior backend release. There is an HTTP availability gap during activation, with no fixed outage guarantee.

Rollback switches to the retained last-good identity through the same path. Forward and rollback transitions preload the departing release's immutable browser assets beside the candidate's current assets. Page leases remain memory-only; the browser's existing exact-byte lease rotation and safe-point checkpoint path handle adoption. This protects the adjacent transition, not arbitrary historical pages. A fresh supervisor start does not preload the retained last-good browser generation merely because its identity appears in the selection file.

A backend switch does not replace the running owner or its code. A candidate with a different owner protocol refuses. An owner without the resynchronize capability keeps its healthy operations, switch and rollback support under a compatible backend, but cannot gain protocol-loss recovery or the delivery-drain notice; the backend does not send the optional action to it. Replacing the owner, including changes to its supervisor closure, requires a deliberate whole-stop with confirmed primary exit and a fresh sealed launch. The control CLI has no stopped-owner selection action: stop followed by the checkout launcher still uses the retained selection. A different owner protocol therefore lacks a complete upgrade command in this CLI. That replacement boundary does not preserve a live Pi process or its pending work. Owner death is not a same-process recovery path. The owner claim refuses an existing claim; this release CLI has no automatic stale-claim takeover. Do not remove a live or uncertain claim.

## Agent presentation control

An ordinary or Durable agent uses the standalone command from a local shell. It is not a Pi extension:

```sh
node ui/cli/control.mts --help
node ui/cli/control.mts layout
node ui/cli/control.mts --workspace <workspace-id> layout
node ui/cli/control.mts --workspace <workspace-id> --actor <label> '{"action":"show","rootId":"<registered-root-id>","path":"README.md","preview":true}'
```

`--state-dir` selects the backend's private state directory; its default matches the server. The layout command lists workspaces or returns one workspace's layout, revision and registered roots. It returns no drafts, transcripts or file contents. Mutations require an exact workspace ID and a closed JSON intent. Unknown fields refuse.

| Intent | Fields and effect |
| --- | --- |
| `show` | `rootId`, relative `path`, optional `paneId` and `preview`: reveal an existing text file, or its Markdown preview. |
| `split` | `paneId`, `axis` (`x` or `y`), and `view`: split with an exact existing [workspace tab](shared/api.ts) shape. |
| `focus` | `paneId`, optional `view`: select the pane or reveal the exact view without keyboard focus. |
| `resize` | `splitId`, integer `ratio` from 20 through 80: adjust a split. |
| `swap` | `splitId`: exchange its sibling branches without closing their views. |
| `notice` | Plain `text`, at most 512 characters: show a nonmodal notice. |

A conversation view identifies an existing agent or the current primary key and epoch. Control never resumes a different saved session. File views require an already registered root; the command does not register folders, supply document content, edit files or save drafts. It never sends model input, starts a host or process, changes execution settings, or exposes a shell endpoint. Existing tabs remain available.

The backend publishes owner-only `control.json` in its private state directory after listen. It contains exactly the loopback origin and current boot ID, without a credential. The CLI uses this file for discovery, not authorization. Local callers access control and ordinary APIs through the same loopback request boundary. An optional actor label is supplied attribution, not verified agent authorship.

**Commands → Agent presentation control** switches control off for the workspace. Actions and their results appear in notices and the bottom status line with the supplied actor label. The bounded private lifecycle log records request identity, actor, workspace, action and result, not file bytes, notice text, drafts or credentials. Unavailable retained logging refuses admission.

Control requires one connected page for the workspace. It refuses ambiguous pages, stale revisions, unsafe geometry, pending navigation, active text selection, composition, menus, dialogs or resize. It also refuses a change that hides or changes the geometry of the active native editor, or changes the pane geometry of a conversation paused at an earlier reading position. Actions on unaffected panes remain available. Logical pane focus does not move the keyboard focus, caret, selection or reading position. Drafts and native Undo remain owned by their existing views.

[Control limits](shared/control.ts) include a 16 KiB request body, a burst of eight mutations with one restored per second, one outstanding request per workspace, eight globally, and a five-second execution deadline. Layout retains its normal pane and geometry limits. The CLI waits at most eight seconds. `applied` means the addressed page acknowledged the layout after persistence and placement. `refused` means application did not begin. `unconfirmed` means application or its acknowledgment is uncertain. The command never retries a mutation or restores an older layout: read the layout before a new intentional action. Reconnection and restart never replay control actions.

The equivalent loopback routes are `GET /api/control/layout`, `POST /api/control/requests`, and `GET /api/control/requests/:id`. Mutations require the exact Origin; reads reject a foreign Origin when supplied. No route requires a credential. A receipt GET with `?wait=1` waits for its result or execution deadline; at most one waiter per request and eight waiters globally are admitted. Control reads have a separate rate bucket with the ordinary HTTP limits, so their rate exhaustion does not consume the browser's bucket. The CLI handles discovery and this bounded wait without polling; direct callers must preserve the same request-boundary and uncertainty rules.

## Security and limits

The server binds only `127.0.0.1`. It validates the exact Host and mutation Origin, rejects foreign fetch metadata, enables no CORS, and serves a fixed asset map: the page at `/`, `/style.css`, `/favicon.svg`, built browser modules under `/web/`, and the shared modules `/shared/api.js`, `/shared/version.js`, `/shared/files.js`, `/shared/health.js`, `/shared/control.js`, and `/shared/inspection.js`. Unknown routes return 404. Static asset requests retain these security checks but bypass API rate and active-request accounting. Static startup reads the retained browser build once, with a 2 MiB per-file bound, a 16 MiB total byte bound, and a 256-entry limit in dist/web; it refuses a missing required asset. A sealed backend serves those bytes as an immutable generation. Release transitions preload the preceding generation for browser adoption under the update rules below.

The personal loopback API has no authentication, launch capability, session cookie, or sign-in view. Any browser profile opens the same plain address. Local processes have full API access; same-user process and browser-profile compromise are outside this boundary. Do not expose the listener through a forwarding proxy or remote route. The server does not read or create authentication state.

CSP forbids inline scripts, evaluation, framing, objects, and foreign connections. Responses use no-store, nosniff, and no-referrer. Model, tool, custom, and diagnostic output is safe text or bounded structured data, never extension HTML. Transcript images are bounded raster data: PNG and JPEG only, at most 8 MiB compressed, 16,777,216 pixels, and 8192 pixels per edge; SVG, GIF, WebP, animated PNG, and signatures are omitted. Sensitive JSON keys and recognizable credential text are redacted in display projections. Same-origin file routes supply bounded text, drafts, explicit saves, directory pages, scoped live updates, and explicit tree operations only for canonical registered working folders. The UI exposes no arbitrary byte-download, shell, signal, or environment endpoint.

Resource bounds are defined in [shared/api.ts](shared/api.ts). They are UI implementation limits, not Pi limits. Oversized requests, exhausted reservations, unresolved-copy capacity, and incompatible protocols reject explicitly. Slow browser clients receive resync instructions instead of blocking process output. Request admission uses elapsed-time rate accounting, not periodic timers. Event streams are bounded independently per workspace; idle age/status displays do not tick.

The browser is not an offline draft ledger. A draft is saved only after the backend acknowledges its complete text, mode, and image references. A browser crash loses local edits and file bytes that never reached the backend. Ordinary execution does not become Durable merely because the browser survives refresh.

## On-demand health

Choose **Health** beside the bottom version identity to read a same-origin `GET /api/health` snapshot. The dialog shows backend PID, start time, uptime, supervisor replacements, serving identity, worker/RPC availability, build state, RSS, and active API request capacity. **Refresh health** requests another snapshot; the closed page and open dialog do not poll. The read does not scan the agent store, select a conversation, or change focus or drafts. Local worker availability is not remote-host readiness. The agent worker reads unavailable while its worker is down or the last catalog scan failed, and then carries a one-line reason of at most 160 characters (the roster error with each whitespace run collapsed to one space and a cut ending in an ellipsis, for example "Catalog directory is absent"); `reason` appears only on an unavailable service. The Primary RPC line reads "idle (no primary running)" when the API state is `stopped`, which means no primary is running, not a failure; a stopped or failed primary shows its own error and exit code or signal in its status. Missing or invalid health facts produce an explicit unavailable result, not a healthy default. Health remains separate from browser connection recovery.

## State and delivery

The backend owns private atomic files beneath `--state-dir`:

- `instance.json`: installation identity and state format.
- `lock.json`: exclusive UI state-root ownership; a live or unknown owner refuses another backend.
- `lock-recovery.json`: persistent macOS kernel-lock guard, held for the state owner's lifetime. Its presence alone does not indicate a live owner; do not delete or replace it.
- `control.json`: current loopback origin and boot ID for local CLI discovery; removed on clean shutdown.
- `lifecycle.log`: bounded redacted lifecycle records, not an input or provider-output archive.
- `primaries.json`: saved keys, project paths, and session metadata, never a live PID authority after restart.

Each workspace owns a connection-scoped observation token. Hide or last-client detach closes observation and unused links; native work continues.

`prepare(identity)` negotiates the same attach-only link for an agent that is not selected and returns its supported operations. It never selects, observes, launches a host, or replays input. A disconnected link or a changed retained endpoint is replaced through the same writer-claim check; a connected link with an unchanged endpoint is reused. Preparation never replaces a connected link that an observation uses: if that storage's endpoint changed, preparation refuses, and explicit observation reconnect owns the replacement. Prepared links count toward the storage link bound and close with other unused links on last-client detach. `POST /api/workspaces/:id/targets` with an agent target returns the saved target state, availability, and negotiated capabilities. A stored, unavailable, or incompatible agent keeps its saved draft with every capability false and a reason.

Collaboration threads are read through `collaboration-list/1.0.0` and `collaboration-read/1.0.0`, whose shapes the [agent host contract](../docs/agent-host-contract.md#collaboration-threads) defines. The decoder checks both with exact identities and refuses unknown fields, mixed thread identities, non-consecutive events and a continuation that disagrees with coverage. A thread lives in the storage that created it, so every call goes to that storage's live host over an attach-only link; no retained fallback exists and nothing launches a host. A host that lacks either operation, or advertises another identity, fails with the distinct code `threads_unavailable`, never with a transport or read failure code.

`GET /api/threads` takes no query besides the `workspace` value the browser adds to every request; the thread routes ignore it, because threads belong to storages. It lists the storages that have a live claim in the cached roster, queries at most four at a time, each with its own deadline, and pages each host through its continuation up to the host's own index bound. The answer holds the threads of all hosts without duplicates, open threads first and then the newest update. A total bound and a response byte bound cut the tail of that order and report the cut as `omitted` and `truncated`. `hosts` counts live storages that answered, lacked the operations (`unavailable`) or failed, plus `notRunning`, the other storages whose threads are not listed. `storages` gives the state, code and message of each queried host. `GET /api/threads/read` requires `threadId` and accepts `before` and `limit`; it goes to the storage named inside the thread ID, and `threads_unavailable` answers with HTTP 501. Both routes return display-cleaned text and member and sender identities without names, and unpack a create or revise event into its frame. No thread route or service member calls `collaboration-mutate`.

The adapter implements `task-submit/1.0.0` requests and `task-submit/1.2.0` responses. A successful response contains the admitted submission, conversation, `deduped` flag, target identity, and a result reference bound to the same target, submission, and request. Admission is not a completed model answer. Inspection uses inspect/1.1.0 with the current schema identity in the decoder and an exact match with the installed Durable metadata, through a compatible live link or the independent retained reader. Result inspection forwards an exact native request ID only with a qualified session identity. Request, submission, input-entry and native operation selectors must identify the same submission; native operation IDs are not request aliases. An unavailable result does not invent a submission ID. **Sent and received tasks…** exposes recorded inputs, sent tasks and exact linked answers in the conversation's persistent pane, without typed result identifiers. The [inspection contract](shared/inspection.ts) keeps native selectors, cursors, offsets and coverage separate from protected body previews; result inspection also preserves supplied provider-block and recovery facts. No browser configure control exists. The decoder, worker proxy, and HTTP route keep configure explicitly unavailable, even when the host advertises it.

## Implementation choices

Workspace theme, agent observation visibility, sidebar visibility, sidebar width, and conversation layout use workspace revisions. Card expansion uses a separate target presentation revision so a disclosure cannot conflict with draft text. Reading positions use stable IDs and offsets, not DOM indices. Opaque target keys name private files; raw agent identities never become filenames. Conversation operation and target mutation transactions serialize consistency checks; their external RPC/native waits occur outside that queue. File move admission and identity publication use workspace serialization; the external filesystem wait stays outside that queue. Browser rendering coalesces through animation frames, not a streaming debounce.

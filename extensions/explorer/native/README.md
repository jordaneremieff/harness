# Explorer native app

Explorer is a macOS app with a WKWebView page and a local Swift package for pane placement. The terminal placeholder shows the folder, file and build. Press `q` in the terminal to close, or another key to focus the Explorer window. Use `:open --root <folder> [--path <file>] [--line <line>]` to navigate in the same pane. An argument with spaces or quotes uses JSON double-quote syntax.

## Host and bridge

`ExplorerHost` follows the terminal pane and connects the page to the workspace, notes helper and live Pi route. The main frame sends versioned requests to the reply-capable `explorer` message handler. The host sends events to `explorer.receive`. A root change includes the new root metadata in the `open` event.

The app scheme serves installed HTML, scripts, styles and supporting files. The page content policy disables network requests, frames and inline scripts. The asset scheme accepts opaque image references from the current workspace. It serves supported image types with a separate restricted policy. Navigation outside the bundled page is refused. File reads reject absolute paths, traversal and links that leave the workspace. Git runs without a shell, with optional locks, external diff drivers and repository hooks disabled.

`Workspace` reads files and computes Git reviews. Text reads return at most 4 MiB, with a notice on truncated previews. Image reads stop at 32 MiB. The Files list returns the ordinary inventory and, when enabled in a Git work tree, a separate ignored inventory. Each is limited to 200,000 paths and reports truncation separately. Git lists a wholly ignored folder once with a trailing slash. A separate request reads up to 5,000 immediate entries inside the folder after expansion, without following links outside the workspace or into Git metadata. Search returns at most 2,000 results and uses a bounded scan for paths not covered by Git. `ExplorerWatch` coalesces file and repository changes through FSEvents.

`markdown.render` reads `.md` and `.markdown` through the same file boundary and returns source metadata and safe GitHub-flavoured HTML. The app uses swift-cmark 0.9.0 with source positions, tables, strikethrough, autolinks, tag filtering and task lists. It omits raw HTML and rejects unsafe link destinations. Markdown images resolve relative to the file inside the workspace; image requests use the same Git revision as the Markdown source. The page never fetches remote images. The host accepts only HTTP, HTTPS and `mailto` for external links. The browser-only fixture uses a small renderer for headings, paragraphs, lists, links and fenced code; the native app defines the full rendering behaviour.

`file.read` returns an `editBase` digest only for eligible working-tree text. `file.write` verifies the root identity and SHA-256 base, flushes a staged sibling to disk, and then replaces the regular file with it by `renameat`. It preserves the ordinary permission bits and returns `conflict` when the base does not match. `file.create` uses exclusive creation after creating any missing parents. Both open parents relative to directory descriptors without following links. Neither writes under `.git`. The WebKit editor normalises line endings for display and restores the file's dominant style when it submits text.

`edit.draft` reads, writes, or clears a private record under `pane-v1`, keyed by canonical root and relative path. `edit.paths` lists the keys for the open root without returning the text. Records include the unsaved text, SHA-256 base, and line-ending style; the host retains at most 32 records per root. Both requests verify the root identity, and the page flushes pending draft writes on navigation, root changes, and normal close. The browser dev bridge uses the disposable Git fixture for file operations and keeps drafts in memory.

`NotesHelper` runs the bundled Node writer with a 1 MiB request limit, a 16 MiB response limit and a ten-second deadline. The writer owns note, review and recent-root records. The host saves page preferences, positions and unsent card drafts as private records. A draft belongs to one root and file. A normal close gives the page a brief opportunity to finish pending draft writes. `LiveClient` consumes a one-use private file and sends authenticated requests only to its loopback endpoint. It does not follow redirects. A pane without a live connection still reads and saves notes.

## Build and checks

From the repository root, run `node extensions/explorer/native/build.mts` to build and install the app. Use `PI_EXPLORER_APP` to select a private install path instead of the configured app location. Run `node extensions/explorer/native/build.mts test` for the Swift tests. The app bundle contains its web page, notes helper and build manifest. `Licenses/swift-cmark-COPYING` carries the parser's licence notices and ships in the app's Resources.

Run the binary inside the bundle with `--pane --store <directory> --root <folder>`. Pass `--path <relative-path>` and `--line <line>` to select a location. Pass `--ignored show|hide` to choose whether that pane shows Git-ignored entries in its Files list. The default is `show`; navigation does not change it. Pane mode requires a terminal.

Run the same binary with `--verify` to drive the bundled page through its real bridge, a disposable Git repository, a notes store and a local test endpoint. Run it with `--export-image --out <png> --width <points> --height <points> --root <folder>` to export a WebKit image. Add `--appearance dark|light`, `--path <relative-path>`, `--line <line>`, `--ignored show|hide` or `--script <file.js>` as needed. Both checks use a transparent window without app activation or keyboard focus.
